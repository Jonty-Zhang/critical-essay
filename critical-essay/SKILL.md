# critical-essay：中文课程思辨论文

一句话：**先想清楚争的是什么、对方最强的说法是什么，再挑结构，最后用学术的平实语言写出来。**

本 skill 只管内容：立场、论证、结构、正文语言、参考文献条目。排版、Word、PPT 不归这里，用户会自己调用别的 skill。

## 必读文件

| 文件 | 什么时候读 |
|---|---|
| `references/structures.md` | 第 2、3 步，判断争点、推荐结构 |
| `references/toulmin-unit.md` | 第 4、5 步，搭论证蓝图、写分论点段落 |
| `references/critical-tests.md` | 第 4 步检验论证、第 6 步自检 |
| `references/language.md` | 第 5 步动笔前、第 6 步自检 |
| `examples/worked-example.md` | 第一次用本 skill 时读一遍，看一个议题从头走到成文 |

不许凭印象跳过。读过一次、会话里还记得的，后续可以不重读。

## 两种入口

- **新写**：用户给了题目、要求或材料 → 从第 1 步开始。
- **改论证**：用户给了初稿 → 先读全文，按 `critical-tests.md` 第五节拆出现有论证，列出问题，再从第 3 步接入（结构不用换的话直接到第 4 步）。只改论证和语言，不碰格式。

## 流程

### 1. 收集要求

先从用户给的东西里找：课程名、题目原文、老师的评分要求、指定读物、引用要求、截止前要不要先交提纲。找得到的不问。

找不到但会改变写法的，在第 3 步一并问（不单独开一轮）：
- 引用：没给就按“需要真实文献、GB/T 7714—2015 著录”处理。
- 立场：题目没限定、用户也没表态时，第 3 步顺带给两个可守的立场让用户选。

### 2. 分析议题（内部完成，结果写进第 3 步的消息）

1. **判断争点**：按 `structures.md` 第一节，判断核心分歧是事实、定义、价值、因果还是对策。一篇论文常有一个主争点，外加一两个要先解决的前置争点。
2. **界定概念**：题目里的关键词，课程语境里怎么理解？有没有容易偷换的义项？
3. **摆出立场光谱**：至少列两种对立的、讲得通的立场。对方立场按“Rapoport 规则”复述到对方自己会认可的程度（`critical-tests.md` 第三节）。
4. **定中心主张**：一句话，带上限定条件（在什么范围内、什么条件下成立）。“应当辩证看待”不是主张。

### 3. 推荐 2–3 个结构，让用户挑

每次都要停下来让用户挑。用户已经点名了结构就照办，跳过这一步。

按 `structures.md` 第二节的匹配表选候选，每个候选写清：
- 结构名，一句话说明它怎么组织全文
- 为什么适合这个议题
- 代价（会弱在哪里）
- 章节骨架预览，3–6 行，写到“第几部分论什么”

有提问工具（AskUserQuestion）就用工具，推荐项放第一个。第 1 步缺的信息、第 2 步的立场选择，放在同一轮里问。

### 4. 搭论证蓝图

用户选定结构后，不再请示，直接做：

1. 按选定结构排出章节。
2. 每个分论点写成一个图尔敏单元：主张、理由、依据、保证、支援（需要时）、限定、反方与回应。格式见 `toulmin-unit.md` 第二节。
3. 给每个单元标出用的是哪种论证型式（诉诸权威、因果、类比……），按 `critical-tests.md` 第一节的关键问题逐个过一遍。答不上来的关键问题，要么补证据，要么收窄主张，要么写进反方回应。
4. 证据：用户给的材料优先。需要外部文献时，检索并核实真实存在（作者、题名、年份、出处都对得上）再用。核实不了的不引，换一条不依赖它的论证，或者在交付时告诉用户这里缺什么证据。**绝不编造文献、数据、引语、页码。**

蓝图不单独交给用户确认，写完直接进入第 5 步；交付时作为单独的文件给出。用户事先说过“先看提纲”的除外。

### 5. 成文

动笔前读 `language.md`。要点：

- 结构名、“图尔敏”“保证”“限定词”这类术语**不出现在正文里**。读者看到的是一篇论文，不是一张论证表。课程要求分析论证结构的除外。
- 引言要交代争议本身：谁在争、争什么、本文站哪边、全文怎么走。不要从“随着社会的发展”写起。
- 每个分论点段落按 `toulmin-unit.md` 第三节的顺序写，保证该说出来的时候要说出来。
- 反方观点用它最强的形式写，篇幅要够，回应要落在对方的理由上，不是落在对方的动机上。
- 结论回到限定后的中心主张，说清本文论证到了哪一步、哪些问题本文没有解决。不喊口号，不展望未来。
- 参考文献：只列正文真的引用过的，按用户要求或 GB/T 7714—2015。

### 6. 自检

两遍，都过了才交：

1. **论证**：`critical-tests.md` 第四节的清单逐条过。
2. **语言**：`language.md` 末尾的清单逐条过，再跑脚本：

```bash
python3 ~/.claude/skills/critical-essay/scripts/lint_prose.py 论文题目.md
```

脚本报出的每一处都要看：是真问题就改，是合理用法（比如引文里的原话）就留着，并能说出理由。脚本没报不等于没问题，它只查得到词和标点层面的毛病。

### 7. 交付

- 正文（Markdown；用户指定了文件位置就写到那里，否则写到当前工作目录，文件名用论文题目）。
- 论证蓝图（单独一个文件，`论文题目-论证蓝图.md`）：中心主张，各分论点的主张、保证、限定，回应了哪些反方。蓝图和正文分开放，脚本只检查正文文件。
- 需要用户补的东西：缺的证据、没能核实的文献、需要用户本人经历或课堂内容才能写的地方。
- 不写“希望对你有帮助”，不在正文里留任何对话痕迹。

## 硬规则

- 不编造文献和数据。
- 不和稀泥：全文要有一个能被反驳的中心主张。承认对方有道理，不等于放弃立场。
- 不稻草人：复述对方时，对方读了要能点头。
- 结构给用户挑，用户点名的结构照用，不擅自换。
- 只管内容，不做排版。
